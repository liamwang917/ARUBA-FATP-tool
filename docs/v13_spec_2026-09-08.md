This document is the authoritative implementation contract for V13.6. V12 remains available in `src/build_summary.py` for regression comparison. Existing V13 code must be revised to this contract before it is considered current.

## 1. Scope

V13 standardizes ARUBA FATP MIC/PREMIC production data into Excel summary workbooks.

V13 is responsible for:

- reading supported compressed FATP packages directly;
- optionally reading a compressed RawData enrichment package;
- discovering MIC/PREMIC and Online/Offline runs;
- parsing Main Station metadata and item values;
- parsing detailed FR/THD/Phase/Noise data;
- matching RawData to FATP runs when RawData is supplied;
- producing standardized workbook sheets;
- runtime QC/logging.

V13 is not responsible for:

- requiring RawData for normal FATP summary generation;
- applying the future dedicated Limit Excel template;
- deriving PASS/FAIL from Low/High limit columns;
- N / Mean / Max / Min / Range / STDEV statistics;
- dashboards/charts;
- APx section-level `Test Result:` parsing.

## 2. Input archives

### 2.1 FATP packages

At least one FATP package is required:

```text
ARUBA_MIC.<archive>
ARUBA_PREMIC.<archive>
```

MIC and PREMIC may be supplied separately or together.

### 2.2 RawData package — OPTIONAL

```text
RawData_RD.<archive>
```

RawData is an optional enrichment source.

If RawData is not supplied:

- FATP parsing and workbook generation continue normally;
- RawData-derived frequency cells remain blank;
- `RawData_Match_Status = NOT_PROVIDED` internally / in Metadata;
- absence of RawData is not an error and must not be reported as `UNMATCHED`.

### 2.3 Supported archive formats — V13.6

The user-facing archive selector must not be limited to ZIP.

Required supported formats:

```text
.zip
.7z
.tar
.tar.gz
.tgz
```

Implementation guidance:

- `.zip` → Python standard library `zipfile`
- `.tar`, `.tar.gz`, `.tgz` → Python standard library `tarfile`
- `.7z` → `py7zr`

The archive abstraction should be generic (for example `ArchiveCsvReader`) so scanner/parser code does not depend on one archive format.

RAR is not required by V13.6.

Users should not need to extract archives manually.

## 3. FATP path discovery

MIC and PREMIC use the same path/data structure. Only Test Type naming differs.

Conceptual path:

```text
<TestType>/Online|Offline/YYYYMM/YYYYMMDD/<Station>/PASS|FAIL/<RunFolder>/*.csv
```

The scanner must discover the structure recursively and must not hard-code month/date/path depth.

Each imported run carries:

```text
Test_Type = MIC | PREMIC
Mode      = Online | Offline
```

`Test_Type` comes from the path and is cross-checked against Main Station CSV `station_id`:

```text
MIC    <-> ARUBA_MIC
PREMIC <-> ARUBA_PREMIC
```

The path station folder (for example `ARUBA-MIC-01`) is the workbook `Station` context. `tester_id` is used as a cross-check when available.

Path/metadata disagreement is a runtime QC warning only.

## 4. Main Station CSV

Confirmed row format:

```text
<item_key>,<result_flag>,<value>,<low_limit>,<high_limit>,<error_code>
```

Interpretation:

- Column A: item key
- Column B: item-level result flag for applicable measurement rows
  - `1` → `PASS`
  - `0` → `FAIL`
  - missing/invalid → blank Result
- Column C: item value
- Columns D/E: Low/High limits — recognized but not used/output in V13
- Column F: test-item / step code — not required in workbook output

The parser keys on Column A `item_key`, never fixed row number.

### 4.1 Complete A→C capture for Metadata — V13.6

`01_Metadata` must capture **every Main Station item found in Column A and its corresponding Column C value**.

Do not maintain a small whitelist of only known keys.

Examples include, but are not limited to:

```text
uut_sn
tsr_id
op_id
station_id
tester_id
test_sw_ver
test_start_time
sfis_get_mac
FR100
FR125
...
FR7500
Sensitivity
THD
Phase
Noise
SNR
test_end_time
total_test_time
```

Metadata union rule across runs:

1. Preserve Main Station item order from the first run.
2. If later runs introduce new item keys, append those keys in first-seen order.
3. Missing items for a run are blank.
4. Values come from Column C.
5. IDs such as `tsr_id`, serial numbers and MAC-like values must be preserved as text where numeric coercion would lose formatting/precision.
6. Measurement values may be written as Excel numbers when safely parseable.
7. `test_start_time` / `test_end_time` should support production formats with fractional seconds and be written as real Excel datetime values when parseable.

The parser may still keep standardized internal aliases (`sn`, `run_id`, etc.) for matching/report logic, but Metadata output must not discard Main Station A→C items.

## 5. FATP detailed CSV classes

### 5.1 FR CSV

The selected FR CSV supplies detailed:

```text
FR
THD
Phase
```

V13 does not parse or use APx section `Test Result:` fields.

`FR_File_Result` is derived from the selected FR filename:

```text
*_FR_PASS_*.csv -> PASS
*_FR_FAIL_*.csv -> FAIL
```

If multiple FR CSV candidates exist in one run, select the latest timestamped candidate and emit runtime QC information.

### 5.2 Noise CSV

The selected Noise CSV supplies the detailed Noise spectrum.

If Noise CSV is absent, detailed Noise values remain blank.

## 6. RawData

When supplied, RawData has the conceptual structure:

```text
RawData_RD/
├─ MIC/**/*.csv
└─ PREMIC/**/*.csv
```

Only RawData under the matching Test Type subtree is eligible.

RawData filename PASS/FAIL may be retained internally for matching/QC:

```text
*_FR_PASS_*.csv -> PASS
*_FR_FAIL_*.csv -> FAIL
```

RawData section mapping:

| RawData section | Summary destination |
| --- | --- |
| `FR_Original` | `02_FR_original` |
| `FR_1/12smooth` | `04_FR_1_12` |
| `FR_1/3smooth` | intentionally unused |

Invalid/empty RawData sections remain blank; do not generate fake zero data.

If RawData is not supplied, scanner/matcher is skipped and state is `NOT_PROVIDED`.

## 7. `Test_Time` semantics — V13.6

`Test_Time` must follow the **source CSV filename timestamp for the data shown on that sheet**. It must not globally reuse Main Station `test_start_time`.

Timestamp extraction rule:

- Locate the final timestamp token in the source CSV filename.
- For 15-digit tokens such as `202609101633182`, use the first 14 digits as `YYYYMMDDHHMMSS` for `Test_Time`.
- Preserve the full 15-digit token separately when it is the original run identifier; do not assume the final digit is fractional seconds.
- For standard 14-digit filename timestamps, parse directly as `YYYYMMDDHHMMSS`.
- If the source filename has no parseable timestamp, leave that sheet's `Test_Time` blank and emit runtime QC; do not silently substitute an unrelated timestamp.

Per-sheet source:

| Sheet | `Test_Time` source |
| --- | --- |
| `01_Metadata` | Main Station CSV filename timestamp |
| `02_FR_original` | matched RawData CSV filename timestamp; blank when no matched RawData |
| `03_FR_1_3` | selected FR CSV filename timestamp |
| `04_FR_1_12` | matched RawData CSV filename timestamp; blank when no matched RawData |
| `05_THD` | selected FR CSV filename timestamp |
| `06_Phase` | selected FR CSV filename timestamp |
| `07_Noise` | selected Noise CSV filename timestamp |
| `08_SNR` | Main Station CSV filename timestamp |
| `09_Sensitivity` | Main Station CSV filename timestamp |

`Start_Time` and `End_Time` are separate Main Station A→C values and do not define sheet `Test_Time`.

## 10. Result semantics

### 10.1 Path_Result

Source: FATP path `/PASS/` or `/FAIL/`.

It remains useful in Metadata and FATP-derived sheets where specified.

### 10.2 FR_File_Result

Source: selected FR filename `FR_PASS` / `FR_FAIL`.

V13.6 displays it only where it directly belongs:

```text
01_Metadata
03_FR_1_3
```

It is removed from `02_FR_original` and `04_FR_1_12` because those sheets are RawData-derived.

### 10.3 THD / Phase / Noise / SNR / Sensitivity Result

Each sheet uses the corresponding Main Station Column B flag:

```text
THD         -> THD row B
Phase       -> Phase row B
Noise       -> Noise row B
SNR         -> SNR row B
Sensitivity -> Sensitivity row B

1 -> PASS
0 -> FAIL
missing/invalid -> blank
```

Missing item does not imply FAIL.

### 10.4 Section Result removed

Do not parse/store/output:

```text
APx_Section_Result
Section_Result
```

## 12. RawData matching

RawData matching runs only when RawData is supplied.

Matching rules:

1. Same Test Type.
2. Exact normalized SN.
3. RawData filename PASS/FAIL may be a supporting internal condition.
4. Compare RawData timestamp against selected FATP FR filename timestamp.
5. Select nearest candidate only inside configurable tolerance.
6. No safe candidate -> `UNMATCHED`.
7. Multiple similarly plausible candidates -> `AMBIGUOUS`.

When RawData is absent, use `NOT_PROVIDED` instead of `UNMATCHED`.

Recommended configuration remains:

| Parameter | Default | Status |
| --- | --- | --- |
| `rawdata_max_time_delta_sec` | `60` | PROPOSED until same-batch validation |
| `rawdata_ambiguous_margin_sec` | `5` | PROPOSED |
| `sn_normalisation` | `upper+strip` | current design |
| `frequency_axis_tolerance` | `0.0` | current design |

Each RawData file may be consumed by at most one FATP run.

RawData filename result and mismatch information may remain in the internal model / Metadata for traceability, but must not appear in sheets 02/04.

## 13. Retest handling

Keep all historical runs.

`Latest_Run` grouping key:

```text
(Test_Type, Mode, SN)
```

Latest run ordering is based on the Main Station filename `Test_Time` defined in section 7; tie-break by full `Run_ID` text.

`tsr_id` remains opaque text. Do not interpret its final digit as fractional seconds.

## 14. Runtime QC and logging

No Excel Import Log sheet is created.

Useful runtime QC includes:

- unsupported archive type;
- malformed/unreadable archive;
- missing Main/FR/Noise CSV;
- duplicate same-type CSV candidates;
- source filename without parseable timestamp;
- Main Station `test_start_time` / `test_end_time` unparseable production format;
- path Test Type vs `station_id` mismatch;
- path Station vs `tester_id` mismatch;
- Path_Result vs FR_File_Result mismatch;
- RawData matched/unmatched/ambiguous when supplied;
- malformed Main Station rows;
- missing/invalid THD/Phase/Noise/SNR/Sensitivity item result flag;
- frequency-axis mismatch;
- empty/malformed RawData section.

RawData not supplied is normal and not a QC error.

## 15. Frequency validation

Validate every imported row against the sheet reference frequency axis.

Never silently shift values when frequency axes differ.

For a mismatched axis, leave affected frequency data blank and emit runtime QC.

## 16. Excel values and presentation

- Frequency/measurement values are real Excel numbers where safely parseable.
- SN, Run_ID, MAC-like identifiers and result fields remain text.
- Filename-derived `Test_Time` values are real Excel datetimes.
- Main Station `test_start_time` / `test_end_time` support fractional seconds.
- Freeze panes/useful widths are allowed.
- PASS/FAIL conditional formatting is allowed.
- No N/Mean/Max/Min/Range/STDEV block.
- No dashboard/chart.
- Missing measurements remain blank.

## 17. Limit handling — deferred

Main Station Columns D/E contain Low/High limits, but V13 does not:

- output them;
- evaluate them;
- create limit sheets;
- create `Limit_Derived_Result`;
- use them to override Result.

A dedicated Limit Excel template will be integrated later.

## 18. Data governance

The repository is public. Production source files can contain DUT SN, MAC, station, operator, tester and other factory metadata.

- Do not commit production archive/CSV/WAV/XLSX files by default.
- Dataset snapshots may record aggregate metadata/hash only.
- Production-generated workbooks are not committed unless identifiers are approved for public disclosure.
- Public tests use synthetic/redacted fixtures.

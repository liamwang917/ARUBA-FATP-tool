This document is the implementation contract for V13. The V13 entry point is `python -m src.main`; V12 remains available in `src/build_summary.py` during regression testing.

## 1. Scope

V13 standardizes ARUBA FATP MIC/PREMIC data into clean Excel summary workbooks.

V13 is responsible for:

- reading FATP ZIP packages directly;
- optionally reading a RawData ZIP enrichment package;
- discovering MIC/PREMIC and Online/Offline runs;
- parsing detailed FR/THD/Phase/Noise data;
- parsing Main Station scalar/metadata values;
- matching RawData to FATP runs when RawData is supplied;
- producing standardized summary sheets.

V13 is **not** responsible for:

- requiring RawData for normal FATP summary generation;
- applying the future dedicated Limit Excel template;
- deriving PASS/FAIL from Low/High limit columns;
- producing N / Mean / Max / Min / Range / STDEV statistics;
- producing dashboards/charts;
- parsing APx section-level `Test Result:` values.

## 2. Inputs

### 2.1 FATP packages

```text
ARUBA_MIC.zip       optional individually
ARUBA_PREMIC.zip    optional individually
```

At least **one** FATP package must be supplied. MIC and PREMIC may be supplied separately or together.

Examples of valid input combinations:

```text
ARUBA_MIC.zip
ARUBA_PREMIC.zip
ARUBA_MIC.zip + ARUBA_PREMIC.zip
```

### 2.2 RawData package — OPTIONAL

```text
RawData_RD.zip
```

`RawData_RD.zip` is an **optional enrichment source**, not a required input.

If `RawData_RD.zip` is not supplied:

- FATP parsing and workbook generation continue normally;
- `02_FR_original` and `04_FR_1_12` still contain the FATP run rows so row alignment is preserved;
- RawData-derived frequency cells remain blank;
- `RawData_Result` remains blank;
- `RawData_Match_Status` is `NOT_PROVIDED`;
- `RawData_Time_Delta_s` remains blank;
- `RawData_PF_Mismatch` remains blank;
- absence of RawData is not an error and must not be reported as `UNMATCHED`.

The tool reads ZIP files directly. Users should not need to extract them first.

Implementation baseline:

- ZIP access: Python standard library `zipfile`
- Excel output: `openpyxl`
- No pandas/numpy dependency required for V13

## 3. FATP path discovery

MIC and PREMIC use the same path/data structure. Only Test Type naming differs.

Conceptual path:

```text
<TestType>/Online|Offline/YYYYMM/YYYYMMDD/<Station>/PASS|FAIL/<RunFolder>/*.csv
```

The scanner must discover the structure recursively and must not hard-code month/date/path depth.

Each imported run carries:

```text
Test_Type = MIC | PREMIC
Mode      = Online | Offline
```

`Test_Type` comes from the path and is cross-checked against Main Station CSV `station_id`:

```text
MIC    <-> ARUBA_MIC
PREMIC <-> ARUBA_PREMIC
```

The path station folder (for example `ARUBA-MIC-01`) is the workbook `Station` value. `tester_id` is used as a cross-check when available.

A path/metadata disagreement is a runtime QC warning; it does not create an Excel Import Log sheet.

## 4. FATP CSV classes

A run may contain:

- Main Station CSV
- FR CSV
- Noise CSV
- WAV files

### 4.1 Main Station CSV

Confirmed format:

```text
<item_key>,<result_flag>,<value>,<low_limit>,<high_limit>,<error_code>
```

The reviewed sample is headerless, CRLF, six columns per row.

Important V13 interpretation:

- Column A: item key
- Column B: **item-level result flag for measurement rows**
  - `1` -> `PASS`
  - `0` -> `FAIL`
  - missing item/flag -> blank Result
- Column C: value
- Columns D/E: Low/High limits — structurally recognized but **not used in V13**
- Column F: test-item / step code

The parser keys on `item_key`, never fixed row number.

Known metadata keys include:

| Main Station key | Internal / workbook use |
| --- | --- |
| `uut_sn` | SN |
| `tsr_id` | Run_ID (opaque text identifier) |
| `op_id` | Operator |
| `station_id` | Test Type cross-check |
| `tester_id` | Tester / Station cross-check |
| `test_sw_ver` | SW_Version |
| `test_start_time` | Start_Time and Test_Time |
| `sfis_get_mac` | MAC (internal/device identifier) |
| `test_end_time` | End_Time |
| `total_test_time` | Total_Test_Time_s |

Measurement keys include:

```text
FR100 ... FR7500
Sensitivity
THD
Phase
Noise
SNR
```

Main Station values are station-check/scalar data. They do not replace the detailed curve sources defined in section 7.

### 4.2 FR CSV

The selected FR CSV supplies detailed:

```text
FR
THD
Phase
Sensitivity
```

V13 **does not parse or use APx section `Test Result:` fields**.

`FR_File_Result` is derived only from the selected FR filename:

```text
*_FR_PASS_*.csv -> PASS
*_FR_FAIL_*.csv -> FAIL
```

If multiple FR CSV candidates exist in one run, select the latest timestamped candidate. Candidate conflicts are runtime QC information.

### 4.3 Noise CSV

The selected Noise CSV supplies the detailed Noise spectrum.

If Noise CSV is absent, detailed Noise values remain blank.

## 5. RawData structure and optional behavior

When supplied, `RawData_RD.zip` has the conceptual structure:

```text
RawData_RD/
├─ MIC/**/*.csv
└─ PREMIC/**/*.csv
```

Only RawData under the matching Test Type subtree is eligible.

RawData PASS/FAIL comes from its filename token:

```text
*_FR_PASS_*.csv -> PASS
*_FR_FAIL_*.csv -> FAIL
```

RawData section mapping:

| RawData section | Summary destination |
| --- | --- |
| `FR_Original` | `02_FR_original` |
| `FR_1/12smooth` | `04_FR_1_12` |
| `FR_1/3smooth` | intentionally unused |

Invalid/empty RawData sections remain blank; do not generate fake zero data.

Section-boundary matching must use exact section names.

If RawData is not supplied, the RawData scanner/matcher is skipped and the per-run state follows section 2.2 (`NOT_PROVIDED`).

## 6. Output workbooks

Potential outputs:

```text
summary_MIC_Online.xlsx
summary_MIC_Offline.xlsx
summary_PREMIC_Online.xlsx
summary_PREMIC_Offline.xlsx
```

Only generate reports for Test Types actually supplied.

RawData presence or absence does not change which FATP workbooks are generated.

## 7. Workbook sheet contract — LOCKED v13.4

There is **no `00_Import_Log` worksheet**.

Each workbook contains exactly these output sheets:

```text
01_Metadata
02_FR_original
03_FR_1_3
04_FR_1_12
05_THD
06_Phase
07_Noise
08_SNR
```

`Sealing` is removed.

No built-in statistics block is appended to any sheet.

### 7.1 Data-source mapping

| Sheet | Data source |
| --- | --- |
| `02_FR_original` | RawData `FR_Original` when RawData is supplied; otherwise blank data cells |
| `03_FR_1_3` | FATP FR CSV detailed `FR` |
| `04_FR_1_12` | RawData `FR_1/12smooth` when RawData is supplied; otherwise blank data cells |
| `05_THD` | FATP FR CSV detailed `THD` |
| `06_Phase` | FATP FR CSV detailed `Phase` |
| `07_Noise` | FATP Noise CSV detailed spectrum |
| `08_SNR` | Main Station CSV `SNR` scalar |

`FR_1_3` remains the historical compatibility sheet name even though its source is the detailed 80-point FATP FR section.

## 8. Result semantics — LOCKED v13.4

### 8.1 Path_Result

Source:

```text
FATP path /PASS/ or /FAIL/
```

Represents overall run-folder classification.

### 8.2 FR_File_Result

Source:

```text
selected FR CSV filename: FR_PASS / FR_FAIL
```

Used in:

```text
01_Metadata
02_FR_original
03_FR_1_3
04_FR_1_12
```

It is **not displayed in sheets 05-08**.

### 8.3 THD / Phase / Noise / SNR Result

Sheets 05-08 have a generic `Result` column derived from the corresponding Main Station CSV item row, column B:

```text
THD row   column B = 1 -> PASS; 0 -> FAIL
Phase row column B = 1 -> PASS; 0 -> FAIL
Noise row column B = 1 -> PASS; 0 -> FAIL
SNR row   column B = 1 -> PASS; 0 -> FAIL
```

If the corresponding Main Station item does not exist, or column B is not `0`/`1`, `Result` is blank.

V13 does not infer FAIL from a missing item.

### 8.4 Section_Result removed

V13 does **not** parse or store:

```text
APx_Section_Result
Section_Result
```

FR CSV `Test Result:` fields are ignored.

## 9. Metadata contract (`01_Metadata`)

One row per imported run.

Approved snapshot fields:

| Column | Source / meaning |
| --- | --- |
| `Test_Type` | path MIC/PREMIC |
| `Mode` | path Online/Offline |
| `SN` | `uut_sn` |
| `Run_ID` | full `tsr_id` string |
| `Test_Time` | `test_start_time` |
| `Station` | FATP path `<Station>` folder |
| `Operator` | `op_id` |
| `Tester` | `tester_id` |
| `SW_Version` | `test_sw_ver` |
| `Start_Time` | `test_start_time` |
| `End_Time` | `test_end_time` |
| `Total_Test_Time_s` | `total_test_time` |
| `Sensitivity_dBFS` | Main Station `Sensitivity` value |
| `SNR_dB` | Main Station `SNR` value or blank |
| `Path_Result` | FATP PASS/FAIL folder |
| `FR_File_Result` | selected FR filename |
| `Latest_Run` | retest handling, section 12 |
| `RawData_Result` | matched RawData filename PASS/FAIL; blank if RawData not supplied |
| `RawData_Match_Status` | `MATCHED` / `UNMATCHED` / `AMBIGUOUS` / `NOT_PROVIDED` |
| `RawData_Time_Delta_s` | matching time delta or blank |
| `RawData_PF_Mismatch` | RawData_Result vs FR_File_Result mismatch flag; blank if RawData not supplied |

`MAC` is retained internally for traceability but is not required in the approved public-facing snapshot contract. If exposed later, it must remain text and be explicitly enabled.

### 10.2 `03_FR_1_3`


`Result` comes from the corresponding Main Station item column B as defined in section 8.3.

### 10.4 `08_SNR`

- `SNR_dB` = blank

## 11. RawData matching

RawData matching is performed **only when `RawData_RD.zip` is supplied**.

When RawData is not supplied, do not instantiate a matching attempt and do not classify any FATP run as `UNMATCHED`; use `NOT_PROVIDED` as defined in section 2.2.

When RawData is supplied, it does not reliably identify Online/Offline from its directory alone.

Matching rules:

1. Same Test Type.
2. Exact normalized SN.
3. RawData filename PASS/FAIL is a supporting condition.
4. Compare RawData timestamp against the selected FATP FR timestamp.
5. Select nearest candidate only inside a configurable tolerance.
6. No safe candidate -> `UNMATCHED`.
7. Multiple similarly plausible candidates -> `AMBIGUOUS`.

Never guess Online/Offline when the match is unsafe.

Recommended configuration:

| Parameter | Default | Status |
| --- | --- | --- |
| `rawdata_max_time_delta_sec` | `60` | PROPOSED until same-batch RawData/FATP validation |
| `rawdata_ambiguous_margin_sec` | `5` | PROPOSED |
| `rawdata_pass_fail_mode` | `soft` | current design |
| `sn_normalisation` | `upper+strip` | current design |
| `frequency_axis_tolerance` | `0.0` | current design |

Each RawData file may be consumed by at most one FATP run.

`RawData_PF_Mismatch` compares:

```text
RawData_Result vs FR_File_Result
```

It does not compare RawData_Result against Path_Result.

Unmatched/ambiguous RawData-sourced sheets keep the run row and leave frequency values blank.

## 12. Retest handling

Keep all historical runs.

`Latest_Run` grouping key:

```text
(Test_Type, Mode, SN)
```

Ordering:

1. `Test_Time = test_start_time` descending
2. `Run_ID` text descending as tie-break

Exactly one valid run in each group receives `Latest_Run = TRUE`.

`tsr_id` is retained as an opaque full-text `Run_ID`; V13 does not interpret its final digit as fractional seconds.

## 13. Runtime QC and logging

V13 does not create an Excel Import Log sheet.

The implementation should still surface QC through console/runtime log and/or a sidecar log if implemented.

Useful QC events include:

- missing Main/FR/Noise CSV;
- duplicate same-type CSV candidates;
- selected duplicate candidate;
- path Test Type vs `station_id` mismatch;
- path Station vs `tester_id` mismatch;
- Path_Result vs FR_File_Result mismatch;
- RawData matched/unmatched/ambiguous when RawData is supplied;
- RawData_Result vs FR_File_Result mismatch;
- malformed Main Station rows;
- missing THD/Phase/Noise/SNR item;
- invalid B-column result flag;
- frequency-axis mismatch;
- unparseable date/time;
- empty/malformed RawData section.

`RawData_RD.zip` not being supplied is a normal supported mode, not a QC error.

These QC events do not add rows/sheets to the summary workbook.

## 14. Frequency validation

Validate every imported row against the sheet reference frequency axis.

Never silently shift values when frequency axes differ.

For a mismatched axis, leave the affected frequency data blank and emit a runtime QC warning.

## 15. Excel values and presentation

- Frequency/measurement values are real Excel numbers.
- `SN`, `Run_ID` and result fields remain text.
- `Test_Time`, `Start_Time`, `End_Time` are real Excel datetimes.
- Freeze panes and useful widths are allowed.
- PASS/FAIL conditional formatting is allowed.
- No `N / Mean / Max / Min / Range / STDEV` block is generated.
- No dashboard/chart is generated in V13.
- Empty/missing measurements remain blank.

## 16. Limit handling — deferred

Main Station columns D/E contain Low/High limits, but V13 does not:

- output them;
- evaluate them;
- create `Station_Limits`;
- create `Limit_Derived_Result`;
- use them to override Result.

A dedicated Limit Excel template will be integrated later.

## 17. Data governance

The repository is public. Production source files can contain DUT SN, MAC, station, operator, tester and other factory metadata.

- Raw CSV/WAV/ZIP files are not committed by default.
- Dataset snapshots record aggregate package metadata/hash only.
- Production-generated workbooks are not committed unless identifiers are approved for public disclosure.
- Synthetic/redacted fixtures should be used for public tests.

Recommended V13 structure:

```text
src/
├─ main.py
├─ config.py
├─ zip_reader.py
├─ run_scanner.py
├─ rawdata_scanner.py
├─ matcher.py
├─ models/

│  ├─ fr_parser.py
│  ├─ noise_parser.py
│  └─ rawdata_parser.py
└─ reports/
   └─ summary_builder.py
```

MIC and PREMIC share the same parser pipeline unless real format divergence is later found.

Regression tests should use synthetic fixtures, including:

- normal PASS run;
- Path FAIL / FR PASS run;
- THD B-column FAIL;
- SNR B-column FAIL;
- missing Noise/SNR item;
- duplicate FR CSV;
- RawData NOT_PROVIDED;
- RawData MATCHED / UNMATCHED / AMBIGUOUS;
- RawData PASS/FAIL mismatch;
- frequency-axis mismatch.

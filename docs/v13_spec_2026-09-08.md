## Scope

This document defines the current V13 architecture and data contract for the ARUBA FATP summary tool.

V13 is intended to support both MIC and PREMIC with one shared parsing/reporting pipeline.

## 1. Inputs

Primary FATP packages:

```text
ARUBA_MIC.zip
ARUBA_PREMIC.zip
```

RawData package:

```text
RawData_RD.zip
```

The tool should read ZIP files directly. Users should not need to extract them first.

Dependency baseline: ZIP access uses the Python standard library (`zipfile`), Excel output uses `openpyxl`. Statistics in section 18 are computed in plain Python. **PROPOSED** — no `pandas`/`numpy` dependency is added in V13.

## 2. FATP path discovery

MIC and PREMIC use the same path/data structure. Only the top-level Test Type name differs.

The scanner must recursively discover paths containing:

```text
Online
Offline
PASS
FAIL
```

Do not hard-code month/date/station depth.

Conceptual example:

```text
<TestType>/Online|Offline/YYYYMM/YYYYMMDD/<Station>/PASS|FAIL/<RunFolder>/*.csv
```

## 3. Test Type and Mode

Each FATP run must carry:

- `Test_Type`: `MIC` or `PREMIC`
- `Mode`: `Online` or `Offline`

MIC and PREMIC share the same parser implementation.

## 4. FATP file classes

A typical run may contain:

- Main Station CSV
- FR CSV
- Noise CSV
- WAV files

V13 should classify CSV files by content/name, not only by fixed path depth.

### 4.1 Classification rules

Classification is evaluated per CSV file in this order. Path depth is never used.

1. **Content signature (authoritative).** Read the file header region and match section/key names:
   - Main Station CSV — contains station summary key/value fields, including an `SNR` key.
   - FR CSV — contains APx section headers `FR`, `THD` and `Phase`.
   - Noise CSV — contains a noise spectrum section whose frequency axis length is an order of magnitude larger than the FR axis (observed 800 vs 80 points).
2. **Filename token (fallback).** Used only when the content signature is inconclusive: case-insensitive match on `FR`, `NOISE`, and station/summary tokens.
3. **Unclassified.** If neither rule resolves the file, do not guess. Mark the file `UNCLASSIFIED`, exclude it from parsing, and record the path in Import Log.

**PROPOSED** — the header scan reads the first 4 KB of each CSV for signature detection.

### 4.2 Duplicate candidates

If multiple same-type CSV files exist in one run, select the latest timestamped file and record all alternatives in Import Log.

## 5. RawData structure

`RawData_RD.zip` is an independent RawData pool:

```text
RawData_RD/
├─ MIC/**/*.csv
└─ PREMIC/**/*.csv
```

Only CSV files under the matching Test Type subtree are eligible for matching.

## 6. RawData section mapping

| RawData section | Summary destination |
| --- | --- |
| `FR_Original` | `FR_original` |
| `FR_1/12smooth` | `FR_1_12` |
| `FR_1/3smooth` | intentionally unused |

Invalid or empty RawData sections must not be imported as fake zero rows. Record them in Import Log.

Section-boundary detection must be exact-name based. Prefix-style section names such as `FR_1/12smooth` and `FR_1/3smooth` must not bleed into each other or into adjacent sections.

## 7. FATP summary mapping

| Summary sheet | Source |
| --- | --- |
| `FR_original` | RawData `FR_Original` |
| `FR_1_3` | FATP FR CSV `FR` |
| `FR_1_12` | RawData `FR_1/12smooth` |
| `THD` | FATP FR CSV `THD` |
| `Phase` | FATP FR CSV `Phase` |
| `Noise` | FATP Noise CSV |

`Sealing` is removed from V13.

## 10. Retest handling

Do not collapse duplicate SNs to one row globally.

Keep all historical runs and add `Latest_Run` so users can filter to the final/latest run when needed.

### 10.1 `Latest_Run` definition

- Group key: `(Test_Type, Mode, SN)`.
- Ordering: `Test_Time` descending; tie-break on `Run_ID` descending.
- Exactly one row per group has `Latest_Run = TRUE`; all others are `FALSE`.
- `Latest_Run` is computed over runs actually imported into that workbook, so a MIC Online workbook never marks a run latest based on an Offline retest.
- Runs with an unparseable `Test_Time` are never marked latest and are counted in Import Log.

## 11. RawData matching

RawData does not reliably identify Online/Offline by path alone.

Matching rules:

1. Same Test Type.
2. Exact SN.
3. PASS/FAIL as a supporting condition.
4. Compare RawData timestamp with FATP FR timestamp.
5. Select the nearest candidate only if within a configurable max tolerance.
6. No safe candidate → `UNMATCHED`.
7. Multiple equally plausible candidates → `AMBIGUOUS`.

Never silently guess Online or Offline.

### 11.1 Configuration parameters

All values live in `config.py` and are overridable without code changes.

| Parameter | **PROPOSED** default | Meaning |
| --- | --- | --- |
| `rawdata_max_time_delta_sec` | `300` | Rule 5 tolerance. Candidates beyond this are discarded. |
| `rawdata_ambiguous_margin_sec` | `30` | Rule 7. If the two best candidates' absolute time deltas differ by less than this, the match is `AMBIGUOUS`. |
| `rawdata_pass_fail_mode` | `soft` | `soft` = PASS/FAIL mismatch is a tie-breaker penalty only; `strict` = mismatch disqualifies the candidate. |
| `sn_normalisation` | `upper+strip` | Applied to both sides before the exact-SN comparison in rule 2. |
| `frequency_axis_tolerance` | `0.0` | Exact match required; see section 15. |

### 11.2 Consumption

Each RawData file may be consumed by at most one FATP run. Once assigned, it is removed from the candidate pool. Runs left without a candidate become `UNMATCHED` and are counted in Import Log.

## 12. Result semantics

Keep these separate:

- `Station Result`
- `APx Section Result`

The existing V12 filename-derived result may disagree with the APx section result. V13 must preserve both meanings independently.

Neither is authoritative until station-limit logic is confirmed. Do not collapse them into a single column.

## 13. SNR handling

SNR is a scalar value read from the Main Station CSV and written to `08_SNR`.

Missing/empty/`NaN` SNR must remain missing (`None`/blank), not be converted to zero.

Import Log should record missing or invalid SNR counts.

## 14. Import Log / QC

Minimum QC counters and events:

- Total runs
- Unique SN
- PASS / FAIL counts
- Main CSV found/missing
- FR CSV found/missing
- Noise CSV found/missing
- Unclassified CSV files (section 4.1)
- Multiple same-type CSV candidates
- Selected latest-file decisions
- Malformed CSV/sections
- Frequency-axis mismatch
- Missing/invalid SNR
- Unparseable `Test_Time` (section 10.1)
- RawData matched/unmatched/ambiguous
- RawData empty sections

## 15. Frequency validation

Do not trust only the first DUT's frequency axis.

Validate every imported row against the sheet reference axis. Any mismatch should be surfaced in Import Log and must not silently shift columns.

A mismatched row is written with its data columns blank rather than shifted, and is flagged in Import Log with the run identifier and the first divergent frequency.

## 16. Metadata sheet contract (`01_Metadata`)

One row per imported run, in the same row order as the data sheets (section 17.2).

| Column | Type | Source |
| --- | --- | --- |
| `Test_Type` | text | path |
| `Mode` | text | path |
| `SN` | text | run folder / CSV |
| `Run_ID` | text | run folder |
| `Test_Time` | datetime | Main Station CSV, converted per section 18.1 |
| `Station` | text | path / Main Station CSV |
| `Operator` | text | Main Station CSV |
| `Tester` | text | Main Station CSV |
| `SW_Version` | text | Main Station CSV |
| `Start_Time` | datetime | Main Station CSV |
| `End_Time` | datetime | Main Station CSV |
| `Total_Test_Time` | number | Main Station CSV |
| `Sensitivity` | number | Main Station CSV |
| `SNR` | number / blank | Main Station CSV, section 13 |
| `Path_Result` | text | path `PASS`/`FAIL` |
| `Station_Result` | text | section 12 |
| `APx_Section_Result` | text | section 12 |
| `Latest_Run` | boolean | section 10.1 |
| `RawData_Match_Status` | text | `MATCHED` / `UNMATCHED` / `AMBIGUOUS` |
| `RawData_File` | text | matched RawData path, blank if unmatched |
| `RawData_Time_Delta` | number (s) | signed delta, blank if unmatched |
| `Main_CSV` | text | source path inside ZIP |
| `FR_CSV` | text | source path inside ZIP |
| `Noise_CSV` | text | source path inside ZIP |

Any field absent from the source CSV is written blank, never as `0` or `"N/A"`.

## 17. Unmatched / ambiguous downstream behaviour

### 17.1 RawData-sourced sheets

`02_FR_original` and `04_FR_1_12` are sourced from RawData. For a run whose match status is `UNMATCHED` or `AMBIGUOUS`:

- The run still gets a row, so row counts stay aligned across all sheets.
- Identifier columns are populated as normal.
- All frequency data cells are left blank — never `0`, never a nearest-guess candidate.
- `RawData_Match_Status` is repeated on the row so the sheet is readable standalone.

For `AMBIGUOUS`, all tied candidate paths are listed in Import Log so the ambiguity can be resolved manually.

### 17.2 Row alignment

Every data sheet contains exactly one row per imported run, in identical order (`Test_Type`, `Mode`, `SN`, `Test_Time` ascending). Row *n* refers to the same run on every sheet, which is what makes cross-sheet comparison and the statistics block valid.

## 18. Workbook formatting and statistics

### 18.1 Values and types

- Frequency and measurement values are written as real Excel numbers, not strings.
- 14-digit timestamps are converted to real Excel datetimes with an explicit number format.
- `SN`, `Run_ID` and result fields stay text.
- Empty sheets carry an explicit status cell explaining why they are empty, instead of appearing blank.

### 18.2 Statistics

Each frequency-domain sheet appends a statistics block below the data rows, separated by one blank row, computed per frequency column: `N`, `Mean`, `Max`, `Min`, `Range`, `STDEV`.

- Blank cells (unmatched runs, axis mismatches) are excluded from `N` and from every statistic.
- **PROPOSED** — Noise sentinel values (`0 Hz`, `-1000`) are excluded from statistics and counted separately in Import Log.

### 18.3 Presentation

Freeze panes at the first data row/column, AutoFilter on the header row, sensible column widths, number formats per sheet, and PASS/FAIL conditional formatting on result columns.

### 18.4 Deferred

Dashboard and distribution charts are out of scope for V13 and are only added once the data model is stable.

## 19. Data governance

This repository is public. FATP and RawData sources contain DUT serial numbers, station, operator, software version and other factory metadata.

- Raw CSV / WAV / ZIP files are not committed.
- `data/snapshots/` records package name, size and SHA-256 only.
- Generated workbooks are committed to `data/outputs/` only after the identifiers they contain are confirmed approved for public disclosure.
- **PROPOSED** — the tool provides no SN masking. If masked output is required for sharing, it is added as an explicit opt-in flag rather than a default.

```text
src/
├─ main.py
├─ config.py
├─ zip_reader.py
├─ run_scanner.py
├─ rawdata_scanner.py
├─ matcher.py
├─ models/
│  ├─ test_run.py

│  ├─ station_parser.py
│  ├─ fr_parser.py
│  ├─ noise_parser.py
│  └─ rawdata_parser.py
└─ reports/
   └─ summary_builder.py
```

MIC/PREMIC should not have duplicated parser implementations unless a future format divergence requires it.

Regression tests use small synthetic FATP and RawData fixtures under `tests/fixtures/`, covering at minimum: a matched run, an `UNMATCHED` run, an `AMBIGUOUS` pair, a frequency-axis mismatch, a missing SNR, and a duplicate same-type CSV.

## 21. Open questions requiring confirmation

These block nothing structurally but should be confirmed against production data before or during implementation.

1. Is `rawdata_max_time_delta_sec = 300` realistic for the gap between a FATP FR run and its RawData capture?
2. Is `rawdata_ambiguous_margin_sec = 30` wide enough to catch genuine Online/Offline ties?
3. Should `rawdata_pass_fail_mode` default to `soft` or `strict`?
4. Are the section-4.1 content signatures correct for PREMIC, or does PREMIC use different section/key names?
5. Does the Main Station CSV actually expose `Operator`, `Tester`, `SW_Version`, `Sensitivity` under those names? Section 16 assumes it does.
6. `SNR` appears both in `01_Metadata` and `08_SNR`. Confirm the duplication is wanted rather than a single location.
7. Confirm the exact Noise sentinel values to exclude from statistics.

## 22. Implementation status

As of 2026-09-09 this document is the locked V13 specification at revision v13.1. The repository's executable code is still V12 (`src/build_summary.py`) until a later PR implements these changes.

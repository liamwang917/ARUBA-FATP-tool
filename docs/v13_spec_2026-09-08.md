## Scope

This document defines the current V13 architecture and data contract for the ARUBA FATP summary tool.

V13 is intended to support both MIC and PREMIC with one shared parsing/reporting pipeline.

## 1. Inputs

Primary FATP packages:

```text
ARUBA_MIC.zip
ARUBA_PREMIC.zip
```

RawData package:

```text
RawData_RD.zip
```

The tool should read ZIP files directly. Users should not need to extract them first.

Dependency baseline: ZIP access uses the Python standard library (`zipfile`), Excel output uses `openpyxl`. Statistics in section 18 are computed in plain Python. **PROPOSED** — no `pandas`/`numpy` dependency is added in V13.

## 2. FATP path discovery

MIC and PREMIC use the same path/data structure. Only the top-level Test Type name differs.

The scanner must recursively discover paths containing:

```text
Online
Offline
PASS
FAIL
```

Do not hard-code month/date/station depth.

Conceptual example:

```text
<TestType>/Online|Offline/YYYYMM/YYYYMMDD/<Station>/PASS|FAIL/<RunFolder>/*.csv
```

## 3. Test Type and Mode

Each FATP run must carry:

- `Test_Type`: `MIC` or `PREMIC`
- `Mode`: `Online` or `Offline`

**CONFIRMED** — MIC and PREMIC file contents are identical in structure; only the Test Type name differs (`ARUBA_MIC` → `ARUBA_PREMIC`). One parser serves both. No PREMIC-specific branch is written unless a future format divergence appears.

`Test_Type` is derived from the path and cross-checked against the Main Station CSV `station_id` value. A disagreement between the two is never silently resolved: the path value is used, and the conflict is recorded in Import Log.

`Mode` comes from the path only. The Main Station CSV carries no Online/Offline indicator.

Where the FATP path contains a station/tester folder such as `ARUBA-MIC-01`, it should also be cross-checked against Main Station CSV `tester_id`. A mismatch is logged; path depth is still not used for file classification.

## 4. FATP file classes

A typical run may contain:

- Main Station CSV
- FR CSV
- Noise CSV
- WAV files

V13 should classify CSV files by content/name, not only by fixed path depth.

### 4.1 Classification rules

Classification is evaluated per CSV file in this order. Path depth is never used.

1. **Content signature (authoritative).** Read the file header region and match first-column item keys or section names:
   - Main Station CSV — headerless, six columns per row, first rows keyed `uut_sn`, `tsr_id`, `op_id`, `station_id` (section 4.3).
   - FR CSV — contains APx section headers `FR`, `THD` and `Phase`.
   - Noise CSV — contains a noise spectrum section whose frequency axis length is an order of magnitude larger than the FR axis (observed 800 vs 80 points).
2. **Filename token (fallback).** Used only when the content signature is inconclusive: case-insensitive match on `FR`, `NOISE`, and station/summary tokens. The Main Station CSV filename is `<uut_sn>_<tsr_id>.csv` and carries no type token, so it is identified by content, not by name.
3. **Unclassified.** If neither rule resolves the file, do not guess. Mark the file `UNCLASSIFIED`, exclude it from parsing, and record the path in Import Log.

**PROPOSED** — the header scan reads the first 4 KB of each CSV for signature detection.

### 4.2 Duplicate candidates

If multiple same-type CSV files exist in one run, select the latest timestamped file and record all alternatives in Import Log.

### 4.3 Main Station CSV format — CONFIRMED

Verified 2026-09-09 against `SR1M08GP262700046_202607061915366.csv` (MIC, PASS, one sample).

Headerless CSV, CRLF line endings, exactly six comma-separated columns on every row:

```text
<item_key>,<index>,<value>,<low_limit>,<high_limit>,<error_code>
```

- Column 2 is `1` on every row in the sample. Treat it as an item index; do not rely on it until a multi-index example is seen.
- Columns 4 and 5 are station limits and may be one-sided. `THD` has no low limit; `SNR` has no high limit; header rows have neither.
- **V13 scope decision:** columns 4/5 are structurally recognized but are not used for workbook output or PASS/FAIL evaluation in V13. Limit application is deferred to a later dedicated limit Excel template integration.
- Column 6 is a test-item / step code (`E0000003723` etc.), present on measurement rows and on `sfis_get_mac`, empty on the remaining header rows.
- Filename is `<uut_sn>_<tsr_id>.csv`.

Header items:

| Item key | Sample value | Maps to |
| --- | --- | --- |
| `uut_sn` | `SR1M08GP262700046` | `SN` |
| `tsr_id` | `202607061915366` | `Run_ID` / `Test_Time` (section 18.1) |
| `op_id` | `S26014718` | `Operator` |
| `station_id` | `ARUBA_MIC` | `Station`, and Test Type cross-check |
| `tester_id` | `ARUBA-MIC-01` | `Tester` and path-station cross-check |
| `test_sw_ver` | `4.1.21.427` | `SW_Version` |
| `test_start_time` | `2026/07/06 19:15:37.026` | `Start_Time` |
| `sfis_get_mac` | `743336400034` | `MAC` — see section 19 |
| `test_end_time` | `2026/07/06 19:16:58.800` | `End_Time` |
| `total_test_time` | `82` | `Total_Test_Time`, seconds |

Measurement items, in file order: `FR100` … `FR7500` (21 one-third-octave points: 100, 125, 160, 200, 250, 315, 400, 500, 630, 800, 1000, 1250, 1600, 2000, 2500, 3350, 4000, 4750, 5300, 6000, 7500), then `Sensitivity`, `THD`, `Phase`, `Noise`, `SNR`.

The parser keys on the item name and never on row position, because item presence and order are not guaranteed to be identical across stations, software versions or FAIL runs.

**CONFIRMED relationship:** for the reviewed sample, all 21 Main Station FR points are exact subsets of the detailed FR CSV curve; Main Station `THD` and `Phase` match the detailed FR CSV values at 1 kHz; Main Station `Noise` matches the Noise CSV at 1 kHz; and `SNR = Sensitivity - Noise`. Therefore these Main Station values are treated as station-check/scalar data, not as replacement sources for the detailed frequency sheets.

The sample contains no overall `Test Result` / `PASS`/`FAIL` row. V13 therefore does not invent a `Station_Result` field from this file. Path/filename/APx result sources remain separate (section 12).

## 5. RawData structure

`RawData_RD.zip` is an independent RawData pool:

```text
RawData_RD/
├─ MIC/**/*.csv
└─ PREMIC/**/*.csv
```

Only CSV files under the matching Test Type subtree are eligible for matching.

## 6. RawData section mapping

| RawData section | Summary destination |
| --- | --- |
| `FR_Original` | `FR_original` |
| `FR_1/12smooth` | `FR_1_12` |
| `FR_1/3smooth` | intentionally unused |

Invalid or empty RawData sections must not be imported as fake zero rows. Record them in Import Log.

Section-boundary detection must be exact-name based. Prefix-style section names such as `FR_1/12smooth` and `FR_1/3smooth` must not bleed into each other or into adjacent sections.

## 7. FATP summary mapping

| Summary sheet | Source |
| --- | --- |
| `FR_original` | RawData `FR_Original` |
| `FR_1_3` | FATP FR CSV `FR` detailed curve |
| `FR_1_12` | RawData `FR_1/12smooth` |
| `THD` | FATP FR CSV `THD` detailed curve |
| `Phase` | FATP FR CSV `Phase` detailed curve |
| `Noise` | FATP Noise CSV detailed spectrum |
| `SNR` | FATP Main Station CSV `SNR` scalar |

`Sealing` is removed from V13.

**CONFIRMED scope decision:** the Main Station CSV's 21-point FR and scalar `Sensitivity`/`THD`/`Phase`/`Noise` values do not replace the detailed sources above. They are retained by the station parser/internal run model for traceability and future limit-template integration. V13 does not add a separate `Station_Check` or `Station_Limits` workbook sheet.

`FR_1_3` remains the historical workbook sheet name for compatibility even though its current source is the detailed 80-point FATP FR section rather than a literal 21-point one-third-octave station curve. This naming can be revisited separately without changing the parser contract.

## 10. Retest handling

Do not collapse duplicate SNs to one row globally.

Keep all historical runs and add `Latest_Run` so users can filter to the final/latest run when needed.

### 10.1 `Latest_Run` definition

- Group key: `(Test_Type, Mode, SN)`.
- Ordering: `Test_Time` descending; tie-break on `Run_ID` descending.
- Exactly one row per group has `Latest_Run = TRUE`; all others are `FALSE`.
- `Latest_Run` is computed over runs actually imported into that workbook, so a MIC Online workbook never marks a run latest based on an Offline retest.
- Runs with an unparseable `Test_Time` are never marked latest and are counted in Import Log.

## 11. RawData matching

RawData does not reliably identify Online/Offline by path alone.

Matching rules:

1. Same Test Type.
2. Exact SN.
3. PASS/FAIL as a supporting condition.
4. Compare RawData timestamp with the FATP run timestamp.
5. Select the nearest candidate only if within a configurable max tolerance.
6. No safe candidate → `UNMATCHED`.
7. Multiple equally plausible candidates → `AMBIGUOUS`.

Never silently guess Online or Offline.

### 11.1 Configuration parameters

All values live in `config.py` and are overridable without code changes.

| Parameter | Default | Status | Meaning |
| --- | --- | --- | --- |
| `rawdata_max_time_delta_sec` | `60` | **CONFIRMED** | Rule 5 tolerance. RawData capture is expected within one minute of the FATP run. Candidates beyond this are discarded. |
| `rawdata_ambiguous_margin_sec` | `5` | **PROPOSED** | Rule 7. If the two best candidates' absolute time deltas differ by less than this, the match is `AMBIGUOUS`. Narrowed from 30 s because the tolerance window is now only 60 s. |
| `rawdata_pass_fail_mode` | `soft` | **CONFIRMED** | PASS/FAIL mismatch penalises a candidate in ranking but never disqualifies it. A mismatch that still wins must be flagged, not accepted silently — see 11.3. |
| `rawdata_time_anchor` | `test_start_time` | **PROPOSED** | Which FATP timestamp the RawData timestamp is compared against. See the note below. |
| `sn_normalisation` | `upper+strip` | **PROPOSED** | Applied to both sides before the exact-SN comparison in rule 2. |
| `frequency_axis_tolerance` | `0.0` | **PROPOSED** | Exact match required; see section 15. |

Note on the anchor: the sample run spans `test_start_time` 19:15:37.026 to `test_end_time` 19:16:58.800, `total_test_time` 82 s. The run is longer than the 60 s tolerance window, so the choice of anchor materially changes which RawData files match. If RawData is captured near the end of the run, anchoring on `test_start_time` will reject valid candidates. This is open question 21.1.

### 11.2 Consumption

Each RawData file may be consumed by at most one FATP run. Once assigned, it is removed from the candidate pool. Runs left without a candidate become `UNMATCHED` and are counted in Import Log.

### 11.3 PASS/FAIL mismatch flagging — CONFIRMED

When the winning candidate's PASS/FAIL disagrees with the FATP run's path/file result, the match is accepted but marked:

- `RawData_Match_Status` = `MATCHED` (the match still stands).
- `RawData_PassFail_Mismatch` = `TRUE`, written to `01_Metadata` and repeated on the RawData-sourced sheets.
- Import Log records a per-run entry with the run identifier, both result values, and the time delta, plus a total mismatch count.

A mismatched match is never written without the flag.

## 12. Result semantics

Keep result sources separate. Do not collapse them into a single ambiguous field:

- `Path_Result` — the `PASS` / `FAIL` folder in the FATP path.
- `FR_File_Result` — `FR_PASS` / `FR_FAIL` encoded in the selected FR filename.
- `APx_Section_Result` — section-level APx `Test Result:` judgement from the FR CSV.

The reviewed Main Station CSV contains no explicit overall station result row, so V13 does not create a separate `Station_Result` field.

V13 also does not derive PASS/FAIL from Main Station columns 4/5. Limit evaluation is intentionally deferred to a future dedicated limit Excel template integration.

Disagreements between `Path_Result`, `FR_File_Result`, and `APx_Section_Result` are counted in Import Log rather than resolved silently.

## 13. SNR handling

SNR is a scalar value read from the Main Station CSV `SNR` item (column 3) and written to `08_SNR`.

Missing/empty/`NaN` SNR must remain missing (`None`/blank), not be converted to zero.

Import Log should record missing or invalid SNR counts.

## 14. Import Log / QC

Minimum QC counters and events:

- Total runs
- Unique SN
- PASS / FAIL counts
- Main CSV found/missing
- FR CSV found/missing
- Noise CSV found/missing
- Unclassified CSV files (section 4.1)
- Main Station CSV rows with a column count other than six (section 4.3)
- Missing expected item keys in the Main Station CSV
- `station_id` vs path Test Type conflicts (section 3)
- `tester_id` vs path station/tester-folder conflicts when that path component is available
- Disagreements between `Path_Result`, `FR_File_Result`, and `APx_Section_Result` (section 12)
- Multiple same-type CSV candidates
- Selected latest-file decisions
- Malformed CSV/sections
- Frequency-axis mismatch
- Missing/invalid SNR
- Unparseable `Test_Time` (section 10.1)
- RawData matched/unmatched/ambiguous
- RawData PASS/FAIL mismatches (section 11.3)
- RawData empty sections

Limit values are outside the V13 QC/report scope and are not evaluated or emitted to Import Log as engineering limit tables.

## 15. Frequency validation

Do not trust only the first DUT's frequency axis.

Validate every imported row against the sheet reference axis. Any mismatch should be surfaced in Import Log and must not silently shift columns.

A mismatched row is written with its data columns blank rather than shifted, and is flagged in Import Log with the run identifier and the first divergent frequency.

## 17. Unmatched / ambiguous downstream behaviour

### 17.1 RawData-sourced sheets

`02_FR_original` and `04_FR_1_12` are sourced from RawData. For a run whose match status is `UNMATCHED` or `AMBIGUOUS`:

- The run still gets a row, so row counts stay aligned across all sheets.
- Identifier columns are populated as normal.
- All frequency data cells are left blank — never `0`, never a nearest-guess candidate.
- `RawData_Match_Status` and `RawData_PassFail_Mismatch` are repeated on the row so the sheet is readable standalone.

For `AMBIGUOUS`, all tied candidate paths are listed in Import Log so the ambiguity can be resolved manually.

### 17.2 Row alignment

Every data sheet contains exactly one row per imported run, in identical order (`Test_Type`, `Mode`, `SN`, `Test_Time` ascending). Row *n* refers to the same run on every sheet, which is what makes cross-sheet comparison and the statistics block valid.

## 18. Workbook formatting and statistics

### 18.1 Values and types

- Frequency and measurement values are written as real Excel numbers, not strings.
- `tsr_id` is a **15-digit** timestamp, not 14: `YYYYMMDDHHMMSS` plus one tenths-of-a-second digit. `202607061915366` is 2026-07-06 19:15:36.6. Parse it as 15 digits and convert to a real Excel datetime with an explicit number format. A 14-digit parser would silently misread the value.
- `test_start_time` / `test_end_time` use `YYYY/MM/DD HH:MM:SS.mmm` and are converted to real Excel datetimes.
- `tsr_id` is also kept as text in `Run_ID` so the original identifier survives round-tripping.
- `SN`, `Run_ID`, `MAC` and result fields stay text. `MAC` in particular must not be coerced to a number.
- Empty sheets carry an explicit status cell explaining why they are empty, instead of appearing blank.

### 18.2 Statistics

Each frequency-domain sheet appends a statistics block below the data rows, separated by one blank row, computed per frequency column: `N`, `Mean`, `Max`, `Min`, `Range`, `STDEV`.

- Blank cells (unmatched runs, axis mismatches) are excluded from `N` and from every statistic.
- **PROPOSED** — Noise sentinel values (`0 Hz`, `-1000`) are excluded from statistics and counted separately in Import Log.

### 18.3 Presentation

Freeze panes at the first data row/column, AutoFilter on the header row, sensible column widths, number formats per sheet, and PASS/FAIL conditional formatting on result columns. `RawData_PassFail_Mismatch = TRUE` is highlighted so flagged matches are visible without filtering.

### 18.4 Deferred

Dashboard and distribution charts are out of scope for V13 and are only added once the data model is stable.

The dedicated limit Excel template integration is also deferred beyond V13. V13 focuses on reliable extraction, matching, standardization, QC, and summary generation.

## 19. Data governance

This repository is public. FATP and RawData sources contain DUT serial numbers, MAC addresses, station, operator, tester, software version and other factory metadata.

- Raw CSV / WAV / ZIP files are not committed.
- `data/snapshots/` records package name, size and SHA-256 only.
- Generated workbooks are committed to `data/outputs/` only after the identifiers they contain are confirmed approved for public disclosure.
- `sfis_get_mac` is a device MAC address. It is carried in the internal model and in `01_Metadata`, but it is a stronger device identifier than the SN and should be reviewed before any workbook containing it is published. Open question 21.4.
- **PROPOSED** — the tool provides no SN or MAC masking. If masked output is required for sharing, it is added as an explicit opt-in flag rather than a default.

## 21. Open questions requiring confirmation

1. **`rawdata_time_anchor`.** The sample run lasts 82 s, longer than the 60 s tolerance. Is RawData captured near `test_start_time` or near `test_end_time`? If near the end, anchoring on start will reject valid matches.
2. **`rawdata_ambiguous_margin_sec = 5`.** Narrowed to suit the 60 s window; needs a real Online/Offline tie to validate.
3. **FAIL-run format.** The confirmed sample is a PASS run. Does a FAIL run add an overall result row, change the error codes in column 6, or truncate the item list?
4. **MAC address publication.** Should `sfis_get_mac` appear in `01_Metadata` at all, given this repository is public?
5. Confirm the exact Noise sentinel values to exclude from statistics.
6. `SNR` appears both in `01_Metadata` and `08_SNR`. Confirm the duplication is wanted.

Resolved in v13.3:

- Main Station vs detailed FR/THD/Phase/Noise overlap: detailed sheets keep their current detailed sources; Main Station values are retained internally as station-check data for traceability/future limit-template integration.
- Limit handling: V13 does not evaluate or output station limits; no `Limit_Derived_Result` is produced.
- Result naming: explicit `Path_Result`, `FR_File_Result`, and `APx_Section_Result` replace the ambiguous `Station_Result` concept.
- `FR_1_3` naming: retained as a historical compatibility name for V13; source remains the detailed 80-point FR section.
